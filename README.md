# Automated Monorail RNA-seq Processing on Slurm

This repository contains scripts designed to automate the execution of the [Monorail RNA-seq processing pipeline](https://github.com/langmead-lab/monorail-external) for multiple samples in parallel on a Slurm high-performance computing cluster.

The Monorail pipeline consists of two main stages: `recount-pump` (per-sample alignment/quantification) and `recount-unify` (aggregation across samples). These scripts wrap the standard `run_recount_pump.sh` and `run_recount_unify.sh` scripts provided by the `monorail-external` repository to handle sample-specific data downloading, setup, execution, and result extraction within dedicated working directories managed by Slurm.

## Prerequisites

Before using these scripts, you must have the following set up on your Slurm cluster environment:

1.  **Slurm Workload Manager:** The batch submission script (`batch_submission.sh`) is written for Slurm.
2.  **SRA Toolkit:** The `fastq-dump` command must be available in your system's PATH for downloading FASTQ files from SRA.
3.  **Singularity:** Singularity (or Apptainer) must be installed and functional. The scripts pull specific Monorail Singularity images.
4.  **Monorail External Scripts:** You need the core scripts from the `monorail-external` repository:
    * `run_recount_pump.sh`
    * `run_recount_unify.sh`
    * `get_mouse_ref_indexes.sh` (or the human version if applicable)
    * `get_unify_refs.sh`
5.  **Monorail Singularity Images:** The scripts use specific versions: `recount-rs5_1.0.6.sif` and `recount-unify_1.0.4.sif`. These will be automatically pulled by `auto_recount3.sh`, but you can also pull them manually beforehand and place them in the `SOURCE_FILES_DIR`.
    ```bash
    singularity pull docker://quay.io/benlangmead/recount-rs5:1.0.6
    singularity pull docker://quay.io/broadsword/recount-unify:1.0.4
    ```
6.  **Initial Monorail Reference Files:** The scripts expect initial reference directories (`grcm38`, `grcm38_unify` for mouse) to be available in the source directory. These are typically generated by running `get_mouse_ref_indexes.sh` and `get_unify_refs.sh grcm38` once in a reference location.
    ```bash
    # Example to get initial mouse refs in a dir called 'initial_monorail_refs'
    mkdir initial_monorail_refs
    cd initial_monorail_refs
    # Assume you have get_mouse_ref_indexes.sh and get_unify_refs.sh here
    ./get_mouse_ref_indexes.sh
    ./get_unify_refs.sh grcm38
    # The directories 'grcm38' and 'grcm38_unify' will be created here.
    # These directories and the get_ scripts should be copied to your SOURCE_FILES_DIR.
    ```
7.  **Input Sample List:** A tab-separated text file listing the samples to process. Based on the script `batch_submission.sh`, the format should be:
    ```
    <GSM_ID_1>\t...\tSRA: <SRA_URL_1>\n
    <GSM_ID_2>\t...\tSRA: <SRA_URL_2>\n
    ...
    ```
    The script extracts the GSM ID from the first column and the SRR ID from the SRA URL in the last column. Ensure the SRA URL format is exactly `SRA: <URL>`.

## How it Works

The automation process involves two main scripts:

1.  **`batch_submission.sh`**: This is the primary script you submit to Slurm (`sbatch batch_submission.sh`).
    * It reads the `INPUT_SAMPLE_LIST` file line by line.
    * For each line, it extracts the **GSM ID** (first column) and attempts to extract the **SRR ID** by fetching the SRA URL (last column) using `curl` and parsing with `sed`.
    * It creates a dedicated, sample-specific working directory under `BASE_WORKING_DIR` (e.g., `/path/to/base/monorail_parallel/monorail-external_GSMxxxxxx`).
    * It copies all necessary Monorail scripts, Singularity images, and initial reference directories from a `SOURCE_FILES_DIR` into the sample's working directory.
    * Finally, it submits a new Slurm job for the individual sample using `sbatch --wrap`, with the working directory set to the sample-specific directory (`--chdir`). The command executed in this individual job is `./auto_recount3.sh <SRR_ID> <GSM_ID> <sample_working_directory>`.

2.  **`auto_recount3.sh`**: This script is executed by the Slurm job for each individual sample.
    * It takes the **SRR ID** (`$1`), **GSM ID** (`$2`), and **sample working directory path** (`$3`) as input arguments.
    * It first checks if the final expected output file (decompressed gene sums) already exists for this sample in the `final_output` subdirectory. If found, it skips the entire process for this sample (`exit 0`).
    * It ensures necessary subdirectories exist.
    * It uses `fastq-dump` with the SRR ID (`$1`) to download the FASTQ file(s) into the sample working directory. It checks for existing FASTQ files to skip the download if they are already present.
    * It creates a `monorail_references` subdirectory and re-runs the `get_mouse_ref_indexes.sh` and `get_unify_refs.sh grcm38` scripts *within* this subdirectory to set up the references needed for the `pump` and `unify` steps for this specific sample's job. It also ensures the necessary Singularity images are pulled into the main sample working directory (though these should have already been copied by `batch_submission.sh`).
    * It executes `run_recount_pump.sh`, passing parameters derived from the script's inputs and the paths within the sample's working directory.
    * It creates a `unify_working` subdirectory and generates a `sample_metadata.tsv` file containing the SRR ID and GSM ID.
    * It executes `run_recount_unify.sh`, passing parameters derived from the script's inputs and the paths within the sample working and unify working directories.
    * After the `unify` step completes, it searches for the gzipped gene sums output file (`*gene_sums.<SRR_ID>.M023.gz*`) within the `unify_working` output structure.
    * It decompresses the found gene sums file and moves it to a `final_output` subdirectory within the sample's main working directory, naming it without the `.gz` suffix.
    * The script is set to exit immediately (`set -e`) if any command fails *after* the initial SRR ID extraction and directory creation phase.

## Setup

1.  **Clone this repository:**
    ```bash
    git clone <repository_url>
    cd <repository_name>
    ```
2.  **Obtain Monorail Source Files and Initial References:** Download or copy the required scripts (`run_recount_pump.sh`, `run_recount_unify.sh`, `get_mouse_ref_indexes.sh`, `get_unify_refs.sh`) and the initial reference directories (`grcm38`, `grcm38_unify`) into a designated source directory (`SOURCE_FILES_DIR`). You will also need to place the downloaded Singularity `.sif` files (`recount-rs5_1.0.6.sif`, `recount-unify_1.0.4.sif`) into this `SOURCE_FILES_DIR`.
3.  **Create Input Sample List:** Prepare your `INPUT_SAMPLE_LIST.txt` file in the format described in the Prerequisites section.
4.  **Configure `batch_submission.sh`:** Edit the `batch_submission.sh` script and configure the following variables:
    * `INPUT_SAMPLE_LIST`: Path to your sample list file.
    * `SOURCE_FILES_DIR`: Path to the directory containing all the necessary Monorail scripts, Singularity images, and initial reference directories.
    * `BASE_WORKING_DIR`: The base path where the sample-specific working directories (`monorail_parallel/monorail-external_GSMxxxxxx/`) will be created.
    * `FILES_TO_COPY`: Ensure this list includes all necessary files/directories that need to be copied from `SOURCE_FILES_DIR` to each sample's working directory.
    * `#SBATCH` directives for the main script (runtime, memory, etc. - usually minimal).
    * `sbatch` options within the loop (`--time`, `--mem`, `--cpus-per-task`) - **configure these according to the resources required per sample job on your cluster.**
5.  **Review `auto_recount3.sh`:** Familiarize yourself with `auto_recount3.sh`. **Pay close attention to the parameters passed to `run_recount_pump.sh` and `run_recount_unify.sh`.**
    * The script currently maps its inputs (`$1`=SRR, `$2`=GSM) to Monorail parameters in a potentially unconventional way (`run_recount_pump.sh` receives GSM as sample ID and SRR as study ID; `run_recount_unify.sh` receives the main working dir as the references dir parameter). **Verify this mapping is what you intend for your specific Monorail application, or modify `auto_recount3.sh` to pass parameters as required by the standard Monorail documentation.**
    * The script hardcodes the genome version (`grcm38`), the number of CPUs (20), and the project info (`sra:101`). Modify these within `auto_recount3.sh` if needed.
    * Ensure `run_recount_pump.sh` and `run_recount_unify.sh` are executable (`chmod +x`).

## Running the Pipeline

1.  Configure the scripts as described above.
2.  Submit the main batch script to Slurm:
    ```bash
    sbatch batch_submission.sh
    ```
3.  Slurm will then queue and submit individual jobs for each sample listed in your input file.

## Outputs

* **Slurm Logs:**
    * `logs/batch_submission_%j.out` / `logs/batch_submission_%j.err`: Logs for the main submission script.
    * `logs/individual_jobs/<GSM_ID>_slurm-%j.out` / `logs/individual_jobs/<GSM_ID>_slurm-%j.err`: Standard output and error logs for each individual sample's Monorail job. Check these for job progress, errors, and output messages from the Monorail scripts.
* **Sample Working Directories:** Each sample will have a dedicated working directory: `${BASE_WORKING_DIR}/monorail_parallel/monorail-external_<GSM_ID>`. This directory will contain:
    * Copies of the Monorail scripts and images.
    * Downloaded FASTQ files.
    * Sample-specific reference files (in `monorail_references/`).
    * Intermediate outputs from Pump (in `output/`).
    * Intermediate outputs from Unifier (in `unify_working/`).
* **Final Output:** The extracted and decompressed gene sums file for each sample will be located in the `final_output/` subdirectory within its sample-specific working directory (e.g., `.../monorail-external_GSMxxxxxx/final_output/*gene_sums.SRRxxxxxx.M023`).

## Important Notes & Caveats

* **Parameter Mapping:** As noted in the Setup section, carefully verify that the parameters passed to `run_recount_pump.sh` and `run_recount_unify.sh` within `auto_recount3.sh` match the expectations documented in the official `monorail-external` README, based on how you intend to use the SRR and GSM IDs. The current mapping might be incorrect for standard Monorail usage.
* **Unifier Reference Path:** The `unify_param3` passed to `run_recount_unify.sh` in `auto_recount3.sh` appears to be incorrect based on the standard Monorail README. It should likely be the path to the reference directory (`${reference_directory}`) instead of the main working directory. **This is a potential bug that needs verification/correction.**
* **Fixed Versions:** The scripts use hardcoded versions for Singularity images (1.0.6 pump, 1.0.4 unify) and the genome reference (grcm38). Ensure these match your requirements and available files. Be aware of potential compatibility issues between Monorail script versions, image versions, and reference file versions, as highlighted in the `monorail-external` README.
* **Work in Progress:** Remember that Monorail itself is described as a work in progress ("beta testing"). Be prepared to encounter and debug issues.
* **Resource Allocation:** The `--time`, `--mem`, and `--cpus-per-task` Slurm directives in `batch_submission.sh` are examples. You **must** adjust these based on the typical resource requirements of a single Monorail job for your data type and reference genome on your cluster.
* **File Paths:** Ensure all paths (e.g., `INPUT_SAMPLE_LIST`, `SOURCE_FILES_DIR`, `BASE_WORKING_DIR`) are correct and accessible from the environment where `batch_submission.sh` is executed.
